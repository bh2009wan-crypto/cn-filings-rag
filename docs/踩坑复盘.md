# 踩坑复盘（作业 3 · A + B）

> 原则：只写**真踩过**的，每条带证据（命令输出、文件、数字）。不写"可能要注意"。

## 1. orgId 不能从股票代码推——错的表现是"静默返回 0 条"

第一版按 `gssh0+代码` / `gssz0+代码` 拼 orgId 查公告，**11 家里 4 家返回 0 条**：
洋河股份（002304）、今世缘（603369）、口子窖（603589）、迎驾贡酒（603198）。

危险的地方在于：**0 条长得像"这家还没发财报"**，如果当常态处理，就会带着少 4 家语料往下走。
真相是这几家的 orgId 是数字 id（`9900008689`、`9900023168`、`9900023518`、`9900023736`），
必须调 `POST /new/information/topSearch/query` 用公司简称换。

处置：`01_resolve_orgids.py` 把"解析不到"和"查到 0 条公告"都算**错误**并非零退出，绝不静默。

## 2. 表格文字会在正文里重复一遍（979 字 → 28 字）

茅台 p27 用 `page.extract_text()` 得到 979 字，但用 `page.filter()` 剔除表格 bbox 内的字符后只剩 **28 字**。
不处理的话，正文块里塞的是表格的散字，检索时"看起来有内容、其实答不了"。

处置：`03_parse_pdf.py` 对每页先 `find_tables()`，再用 `page.filter()` 抠掉表格区域，正文与表格各成一块。

## 3. 页码偏移逐份不同（茅台 0、古井贡酒 +1、五粮液是裸数字）

三种页脚形态都真实存在：

| 公司 | 页脚形态 | 偏移 |
|---|---|---|
| 贵州茅台 | `1 / 110` … `110 / 110` | 0 |
| 古井贡酒 | `~ 141 ~`，末页是 PDF 第 142 页 | **+1** |
| 五粮液 / 泸州老窖 / 洋河股份 | 页脚就是一个裸数字 `8` | 0（需专门加一条正则） |

处置：逐份探测页脚形态、取**众数**偏移、一致性 < 90% 就不用（只保留 `pdf_page`）；
每条引用同时存 `pdf_page` 与 `printed_page`，两种页码都能回溯。

## 4. 同一页会出现两个节首——86 页财报被标错章节

茅台 p25 同时有「第七节 债券相关情况」和「第八节 财务报告」。
第一版"每页只记第一个节首"，结果 **从 p25 到 p109 全被标成"第七节 债券相关情况"**（86 页）。

处置：按"**页内行号**"记录全部节首，切块时按行号分段，每块继承所在段的章节。修好后：8 个节、财务报告 86 页归属正确。

## 5. 表题回溯会抓到"表内行"

pdfplumber 有时把表格的前一两行漏在 bbox 之外，那几行就成了"表格上方的文字"。
朴素做法（取上方最近的非空行当表题）会把 **「结算备付金」「向中央银行借款」** 这种表内行当表题，
更糟的是接着用"表题不同"去判断跨页合并 → 财务报表被切成 4 段。

处置：表题只认带「表/情况/状况/明细」关键词的行；找不到宁可留空（块标签另有"章节·页码"可用）。

## 6. 表内标题 ≠ "只有一格有字的行"

反过来，像「结算备付金」这样的表内行也常常只有一格有字，用"只有一格有字"当表内标题的判据会误判。

处置：改用**单元格几何**判断——只有当首行那**一个**单元格跨越表格宽度 70% 以上（真的是合并单元格）才当表内标题。

## 7. 跨页表必须合并：合并资产负债表横跨 p25–p28

不合并的后果很具体：`所有者权益（或股东权益）合计` 这一行会和表头分家，回答"所有者权益合计是多少"时窗口里只有数字没有表头。

处置：页面贴底（>72%）+ 下页贴顶（<28%）+ 列数一致 + 同一章节 + **后表不自带表头** 才合并。
修好后：合并资产负债表 105 行完整，合并/母公司两个口径都在（`262,096,352,174.36` 对 `158,148,992,327.71`）。

## 8. 模型会假性拒答：它以为现在是 2026 年 5 月

实测（未注入日期时）问"2026 上半年营收"，模型的回答是：
> 当前 2026年5月7日，半年报尚未披露……

它按**内部日期**判断报告是否存在。这类错误在评测里单列 E6（假性拒答）。

处置：提示词首行注入「今天是 2026年9月24日」+ 明令「不要用你内部的记忆判断这些报告是否已发布」。

## 9. thinking 块会吃光 token

`max_tokens=16` 时，返回内容里全是 reasoning、正文为空。
处置：一律传 `thinking={"type":"disabled"}`（实测输出 token 由 132 → 1）；只有质检这种需要"想一下"的环节才开。

## 10. hf-mirror 下不动 1.14GB 的模型

- 直连 hf-mirror 测速：**7.5 KB/s**（1.14GB 要 40+ 小时）
- 单连接续传：~150 KB/s，且多次 `SSL: UNEXPECTED_EOF_WHILE_READING`
- huggingface.co 走 Clash 代理：拿 API 元数据 200，拿 LFS 文件超时
- **ModelScope**：842 KB/s；再叠加 **8 路并行 Range 分片**，十几分钟下完

处置：并发分片下载 + 合并后**校验字节数**（1,191,586,416）与源一致才算成功。

## 11. 同一份公告被两个清单各下一份

茅台 2026 半年报同时出现在 A（11 家 2026H1）和 B（茅台历年）两个清单里，
结果同一份 PDF 存了两份、同一份报告被切两次块 → 训练数据里同一事实重复。

处置：按 `adjunctUrl` 去重；别名条目写 `alias_of` 指向主条目，解析/切块时跳过。

## 12. 报告期标签写错导致文件互相覆盖

`period.replace("H1", "")` 把 `2021H1` 写成 `2021`，于是"2021 年报"和"2021 半年报"
**共用同一个文本文件名** `600519_2021.jsonl`，后写的那份把前面的覆盖了。

处置：报告期一律带 `H1` 后缀；发现后重新解析了 B 的 11 份。**自引用别名**（`alias_of` 指向自己）也是这轮修出来的，它同样会造成整期报告被静默跳过。

## 13. 造数据时"依据原文"很少逐字

实测：模型"抄写"时会漏虚词、把顿号改成逗号，严格 verbatim 会误杀一大半。
处置：分两级——`逐字命中`（等级 2）与 `3-gram 覆盖率 ≥ 0.9`（等级 1，且把覆盖率记进报告）；
覆盖率 < 0.9 的一律丢。**没有把"放宽"藏起来**，`qc_report.json` 里能看到。

## 14. macOS 的 TCC：`ls` 被拒但按完整路径读写单个文件是通的

在桌面目录上 `ls` 报 `Operation not permitted`，但 `stat` / `open()` / `python` 读同一个**具体文件**都正常。
所以判断"文件在不在"不要靠 `ls` 目录，直接测完整路径；项目本体也不要放桌面/文稿/下载（定时任务会读不到）。
