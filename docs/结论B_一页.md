# 作业 B 一页结论：用茅台财报训一个「董秘」

> **最终用的是本机方案**（Apple M2 / MPS），不是 Colab。原因见文末「为什么不在 Colab 跑」。
> 基座：**Qwen3-0.6B**（课件用 Qwen3.5-2B，8GB 内存训不动 2B）；四格定义与判分口径与
> `notebooks/maotai_dongmi_lora.ipynb` 完全一致，两个结果可直接对比。

## 一、语料与数据（做了什么）

| 项 | 数值 |
|---|---|
| 语料 | 贵州茅台 **11 份**：2021–2025 年报 + 2021H1–2026H1 半年报（2026 年报尚未披露，约 2027-04 才出） |
| 规模 | 1,292 页 / 48.8 万字正文 / 2,238 张表 → 4,405 块 |
| 造数据 | 一块原文 → 3 组「投资者提问 → 董秘作答」；**强制逐字抄出「依据原文」**（让"编造"变成可字符串校验的） |
| 引用 | 每条答案末尾**注明出处**：`依据：《贵州茅台 2023 年年度报告》第 18 页`（对齐课件 B② 与课件样例格式） |
| 生成 | 180 + 52 + 92 块，共 **357 条问答**，约 5 分钟（deepseek-flash，8 并发，关闭 thinking） |
| 质检 | 阶段一（脚本）淘汰 6 条；阶段二（模型）判「有据 0/1/2 · 自然 0/1」→ 留 **312 条**（保留率 87%） |
| 人工抽检 | 固定种子 `20260924`、分层抽 **40 条**逐条判 → 弃用 **14 条**（理由：要求逐字引用；**复核后确认 0 条编造**，详见 `docs/抽检记录.md`）<br>→ 最终 **298 条** |
| 划分 | **按块（事实）85/15**：训练 **254 条（96 块）/ 测试 44 条（17 块）**，测试覆盖 9 个报告期 |
| 换问法 | 训练集 **246 条**、测试集 **44 条**（3-gram Jaccard < 0.5 才算"换了"） |
| RAG 对照上下文 | 88 条（测试题 + 换问法题，检索自茅台 11 份报告） |

## 二、训练（本机 M2，8GB 内存）

| 项 | 数值 |
|---|---|
| 基座 | Qwen3-0.6B（0.61B 参数），主干 **bf16** / LoRA 适配器 **fp32**（peft 自动保持） |
| LoRA | r=16、alpha=32、dropout=0.05，target_modules = q/k/v/o/gate/up/down_proj（**探针读出来的，不是抄教程**） |
| 可训练参数 | **10.09M / 0.61B = 1.67%** |
| 训练 | 3 epoch、**48 步**、lr 2e-4、batch 1 × 梯度累积 16、序列上限 192 |
| 耗时 | **639 秒（10.7 分钟）**；loss 3.33 → 约 1.1（逐批有波动，趋势明显下降） |
| 四格评估 | 每格 60 条（测试格 44 全量）+ RAG 对照 44 条；两次评估各约 7 分钟 |

> 三个工程决定值得记：① **M2 上 bf16 比 fp32 快 11 倍**（实测 0.9s vs 10.0s/批）；
> ② 评估与训练必须**分进程**跑，否则 8GB 内存会被 MPS 缓存 + 激活值撑爆（第一次跑就 OOM）；
> ③ 训练脚本做成 `--phase before/train/after/merge`，任何一段挂掉都不用从头再来。

## 四、这些数字说明什么（这才是重点）

### ✅ 训练确实改变了行为，而且改得很干净

**1. 学会了「董秘口吻」**——长度比 2.30 → 1.10（训练前啰嗦到金答案的 2.3 倍，训练后基本对齐）：

| | 回答 |
|---|---|
| 训练前 | 「2021年半年度报告中，**公司未披露**被控股股东及其关联方非经营性占用资金的情况……」 |
| 训练后 | 「**这两项都没有。**……是不适用的」 |

**2. 学会了「报依据」这个格式**——这是最干净的一项：

| | 输出里带「依据：」 | 其中**页码也对**的 |
|---|---|---|
| 训练前 · 格1（训练过） | 0 / 60 | — |
| 训练后 · 格1（训练过） | **56 / 60** | **1 / 56** |
| 训练前 · 格3（没训练过） | 0 / 44 | — |
| 训练后 · 格3（没训练过） | **42 / 44** | **3 / 42** |

**3. 四格的方向都对**：格1 > 格3（0.342 vs 0.302，教过的更好）；格2 < 格1（0.304，换问法掉 11%）；
误拒答 2 → 0。

### ❌ 但它没学会「说什么」

**1. 数字命中全为 0**（格1–格4）：具体数字一个都没答出来。

**2. 连「依据」都只会造格式、不会报对页**：上面那张表最扎眼——**报了依据的 56 条里只有 1 条页码是对的**。
它学会了"末尾就该跟一个像页码的数字"，但完全没记住是哪一页。**格式学到、内容编造**，这正是课件警告的那种失败：
看着像董秘、内容不可信。

**3. 训练过的题也会答反**：问"有没有利润分配预案"，金答案是"没有"，训练后答成
"预案**适用**，要派发现金股利"——措辞像、事实反。

**4. 没训练过的题会编**：问"酒糟、废窖泥怎么处置"，金答案是"交给集团循环经济公司综合利用"，
模型答成"厌氧发酵做饲料喂猪"（F1 却不算低，0.133）。

**5. 格5（RAG 对照）暴露小模型的另一短板**：把检索原文的标题行当内容抄出来
（输出开头是"境与社会责任·第11页】③固废处理情况…"）——0.6B 分不清"材料"与"回答"的分界。
但它的**数字命中是唯一非零的（0.19 → 0.23）**，反过来说明：**事实得靠检索递进来**。

### ⚠️ 两个必须写明的局限

1. **字符 F1 奖励"措辞像"，不保证"事实对"**。F1 从 0.093 涨到 0.342，其中相当一部分来自
   "学会了董秘腔调 + 学会了报依据格式"，**不能读成"能力提升 3.7 倍"**。所以我把
   **数字命中**、**页码正确率**、**人工看逐条**都留在报告里。
2. **基座只有 0.6B**（课件用 2B），容量是硬约束：262/254 条样本不足以让它同时学会口吻与事实。
   换成 Colab 上的 2B 应该会好一些，但"格式易学、事实难学"的结构性结论不会变。

## 五、结论一句话

> **SFT 能让小模型学会「董秘怎么说」（口吻、长度、连"末尾报依据"都学会了），
> 但学不会「董秘说什么」——事实与页码必须由检索递进窗口，这正好是作业 A 存在的理由。**
> 课件那句「什么值得背进权重：稳定的风格、口径、格式；什么留在检索库：常更新的事实、长尾细节、需要溯源的证据」，
> 在我们这组数据上被复现得非常彻底——**连"引用格式"都是格式，而"引用对哪一页"是事实。**

## 六、没做什么 / 与课件的差异（免得看起来比实际好）

- **没上 GRPO**：作业 B 只要求 SFT（GRPO 是课件的深度五，属于另一条线）。
- **没做参数扫描**：只按课件的量级跑一遍（r=16、3 epoch），没做八种配置对照。
- **基座不是课件同款**：Qwen3-0.6B ≠ Qwen3.5-2B。四格口径一致，但**绝对分数不可与课件直接比**。
- **每格评估有上限**：训练过的格子取前 60 条（不是全部 254/246），测试格是全量（44）。
- **引用是脚本补的**：`依据：《…》第 N 页` 由 `12c_add_citation.py` 确定性追加（不是模型生成的），
  所以"页码对不对"是可核验的硬指标——这也是我们能量出 1/56 的原因。

## 七、为什么不在 Colab 跑（如实记录）

Colab 那条路被网络卡死：代理节点在 20 分钟内三次在"通/不通"之间翻转
（`colab.research.google.com` 与 `ssl.gstatic.com` 全 000 ↔ 全 200），
表现为「无法加载显示输出所需的 JavaScript 文件」→「卡在正在连接到 T4」→「`await connected: disconnected`」
→「无法连接到代码执行程序」四种报错轮流出。判据脚本留在 `scripts/check_colab_net.sh`：
**全绿 = 浏览器侧问题，有红 = 节点问题**。

最终改用本机 M2 跑（`scripts/23_local_sft_mps.py`），代价是基座从 2B 降到 0.6B，
好处是**完全不依赖网络、不出配额、可复现**——四格该有的对照一个不少。
Colab 笔记本（`notebooks/maotai_dongmi_lora.ipynb`）保持可用：网络好时随时可以拿它跑 2B 版本，
把两份结果对照着看（口径一致）。
